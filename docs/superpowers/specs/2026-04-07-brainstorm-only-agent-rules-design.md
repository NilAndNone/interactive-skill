# 项目级 AGENT.md 规则文档设计

## 文档目的

本文档定义仓库根目录 `AGENT.md` 的目标、边界和正文结构，用于把本仓库约束为“只做脑暴和文档沉淀”的工作区，避免 Codex 在该仓库内进入实现、写代码或交付补丁的路径。

这份设计文档的目标不是直接代替 `AGENT.md`，而是先把 `AGENT.md` 应包含的规则写清楚，确保后续落盘时约束完整、措辞一致、没有歧义。

## 任务定位

- 类型：项目级规则文档设计
- 目标文件：仓库根目录 `AGENT.md`
- 目标对象：在本仓库内工作的 Codex
- 目标产出：一份强约束的项目级规则文档
- 核心作用：
  - 把本仓库限定为 `brainstorm` 优先的文档工作区
  - 明确本仓库只产出中文文档，不进入实现
  - 让产出物默认面向 `GPT-5.4 Pro` 等具备深度检索能力的模型或研究员执行

## 已确认需求

- `AGENT.md` 放在仓库根目录
- 规则作用域是项目级，覆盖整个仓库
- 文档语气为强约束、不可协商
- 本仓库只用于 `brainstorm`、调研要求梳理、问题设计、需求澄清和文档沉淀
- 不进入代码实现、补丁生成、功能交付等开发路径
- 所有正式产出默认使用中文
- 所有正式文档统一写入 `docs/superpowers/plans/`
- 本仓库中的文档默认写给 `GPT-5.4 Pro` 等有深度检索能力的模型或研究员执行
- 在形成正式文档前，Codex 必须先完成至少 `10` 个脑暴问题
- 用户只做选择题
- 每次提问都必须给出至少 `3` 个选项
- 如果用户要求写代码、实现功能、修 bug 或直接交付实现，Codex 需要提醒“这个仓库不能这么用”，然后把任务重定向为脑暴和文档任务

## 非目标

- 不把本仓库定义成通用开发仓库
- 不为实现、测试、修复、重构提供工作流入口
- 不要求在 `AGENT.md` 中枚举所有禁止技能名称
- 不在 `AGENT.md` 中写死固定的 10 类问题模板
- 不允许把正式产出散落到仓库其他目录

## 推荐文档结构

建议 `AGENT.md` 采用以下结构：

### 1. Scope

说明这是项目级规则文档，适用于整个仓库，并作为 Codex 在此仓库中的默认工作约束。

### 2. Repository Purpose

明确本仓库的唯一用途是：

- 进行 `brainstorm`
- 梳理调研要求
- 设计问题清单
- 沉淀中文文档

同时明确这里不是代码实现仓库。

### 3. Output Audience

明确所有正式文档都应假设目标读者是：

- `GPT-5.4 Pro` 等具备深度检索能力的模型
- 或负责后续执行调研的人类研究员

因此文档必须可直接复制给下游执行者使用，而不是写成松散的说明或笔记。

### 4. Mandatory Workflow

明确 Codex 在本仓库处理任何任务时默认遵循以下流程：

1. 先进入 `brainstorm`
2. 在写正式文档前，至少完成 `10` 个脑暴问题
3. 所有问题都以选择题形式提出
4. 每次提问至少提供 `3` 个选项
5. 用户完成选择后，再整理正式中文文档
6. 正式文档统一写入 `docs/superpowers/plans/`

这里需要强调：

- “至少 10 个问题”是流程门槛，不是建议
- 问题方向可以灵活，但不能跳过问题阶段直接写文档

### 5. Redirect Rules

明确当用户在本仓库中直接要求：

- 写代码
- 改功能
- 修 bug
- 交付实现
- 直接提交开发结果

Codex 的处理方式应为：

1. 先提醒用户这个仓库不能这么用
2. 把请求重定向为脑暴和需求梳理
3. 最终只输出文档，不进入实现

### 6. Output Standard

明确本仓库内的正式文档必须满足以下标准：

- 使用中文
- 结构清晰
- 可直接交给下游强模型或研究员执行
- 约束条件明确
- 输出边界明确
- 证据、要求、格式、风险说明清楚
- 不写成泛泛建议

## 关键规则细化

### Brainstorm 优先

`AGENT.md` 需要把 `brainstorm` 描述成本仓库的默认入口，而不是可选步骤。任何新任务先进入脑暴，再决定文档内容。

### 选择题式交互

`AGENT.md` 需要明确用户在本仓库内主要通过选择题与 Codex 协作：

- Codex 不应把澄清问题写成开放式大问答
- 每次问题都给出至少 `3` 个可选项
- 用户可以选择一个选项，也可以基于选项调整，但交互形式仍以选择题为主

### 仅交付文档

`AGENT.md` 需要明确本仓库的完成标准是“产出高质量中文文档”，不是“交付功能”。因此：

- 可产出：调研任务书、提问模板、需求澄清文档、约束整理文档、执行要求文档
- 不产出：功能实现、代码补丁、测试修改、运行结果修复

### 固定落盘目录

`AGENT.md` 需要明确所有正式文档落到 `docs/superpowers/plans/`，这样仓库内容会保持单一、可预期、便于后续强模型直接读取。

## 建议措辞风格

正文建议采用简短、命令式、强约束语气，例如：

- “本仓库只用于……”
- “任何任务必须先……”
- “不得跳过……”
- “如果用户要求写代码，先提醒……再重定向……”

避免使用模糊措辞，例如：

- “尽量”
- “可以考虑”
- “通常”
- “视情况”

## 验收标准

后续生成的 `AGENT.md` 至少应满足以下验收条件：

- 放在仓库根目录
- 明确说明规则作用域为整个仓库
- 明确声明仓库只做脑暴和文档
- 明确声明默认使用中文
- 明确声明正式文档统一落到 `docs/superpowers/plans/`
- 明确声明正式文档写给下游强模型或研究员
- 明确规定先问至少 `10` 个问题
- 明确规定问题必须是选择题
- 明确规定每次至少给 `3` 个选项
- 明确规定用户要求写代码时要先提醒并重定向

## 风险与注意事项

- 如果规则写得过短，Codex 可能只记住“先脑暴”，但忽略“只交付文档”
- 如果不写清“选择题”和“至少 3 个选项”，Codex 可能退回开放式提问
- 如果不写清目标读者，产出的文档可能更像聊天记录，而不是可交付给下游模型执行的任务书
- 如果不写清落盘目录，仓库内文档可能继续分散

## 最终结论

后续创建的 `AGENT.md` 应当是一份项目级、强约束、中文、以 `brainstorm` 为默认入口的规则文档。它的核心目标不是提升开发效率，而是把本仓库稳定地限制在“脑暴提问 + 调研要求梳理 + 中文文档沉淀”的用途上，并把所有产出统一导向 `docs/superpowers/plans/`，供 `GPT-5.4 Pro` 等具备深度检索能力的模型或研究员继续执行。

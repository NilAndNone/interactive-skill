# 2026-05-05 哈尔滨方向回深圳机票深度调研设计

## 文档目的

本文档定义一份可直接交给其他模型或研究员执行的深度调研任务书，用于研究 `2026-05-05` 从 `哈尔滨 / 长春 / 牡丹江` 出发、返回深圳方向的机票方案，并判断在当前时间点 `2026-04-07` 应该何时购买更合适。

本文档的目标不是直接给出票，而是把调研范围、硬约束、评分方法、证据要求、异常处理和最终输出格式写清楚，确保后续执行稳定、可复核、可比较。

## 任务定位

- 类型：结构化深度调研任务书
- 目标使用者：其他模型或研究员
- 目标产出：标准化的机票调研结果，而不是随意的最低价截图
- 核心问题：
  - 在给定出发地、到达地和当日到达限制下，哪些机票方案综合性价比最高
  - 当前是否适合买票
  - 如果继续等待，应该观察到什么时间点，以及什么价格出现时应立即下单

## 已确认需求

- 出发日期固定为：`2026-05-05`
- 行程类型：单程
- 必须：`2026-05-05` 当天出发、`2026-05-05` 当天到达
- 可接受出发城市：`哈尔滨 / 长春 / 牡丹江`
- 可接受到达城市：`深圳 / 香港 / 澳门 / 广州 / 珠海 / 惠州`
- 最终比较锚点：`深圳坪山站`
- 接受中转
- 中转下限：`60 分钟`
- 中转上限：尽量不超过 `6 小时`
- 票价口径：`单人成人含税裸票`
- 不默认计入：托运行李、选座、餐食、接送机套餐
- 搜索渠道范围：
  - 航司官方
  - 携程
  - 飞猪
  - 同程
  - 去哪儿
  - 航旅纵横
- 性价比定义：综合考虑 `机票价格 + 落地后到深圳坪山站的补交通成本 + 总耗时 + 中转风险`
- 文档用途：写成可直接交给其他模型或研究员执行的提问模板与评估标准

## 非目标

- 不追求只看票面最低价
- 不输出未经核实的“历史最低价”断言
- 不依赖小型、不明来源或不可复核的平台报价
- 不把不满足当日到达条件的方案强行纳入候选

## 推荐执行方式

建议把后续调研分成四步执行：

1. 全面搜索可行航班
2. 对结果做硬筛选
3. 对通过筛选的方案做综合评分
4. 基于价格趋势和临近出发窗口规律做购买时机判断

## 硬约束与筛选规则

后续执行者必须先做硬筛选，不满足任一条件的方案直接淘汰：

- 不是 `2026-05-05` 当天出发
- 不是 `2026-05-05` 当天到达
- 出发城市不在 `哈尔滨 / 长春 / 牡丹江`
- 到达城市不在 `深圳 / 香港 / 澳门 / 广州 / 珠海 / 惠州`
- 中转时长短于 `60 分钟`
- 中转时长明显超过 `6 小时`
- 报价不是 `单人成人含税裸票`
- 报价渠道不在约定范围内

说明：

- 允许 `直飞` 和 `中转`
- 允许跨境到达 `香港 / 澳门`，但必须把后续到 `深圳坪山站` 的补交通和风险纳入比较
- 默认优先统计 `官方或主流 OTA 正常可售的一体化航程`
- `分开买两张票的自拼行程` 只作为高风险补充备选，默认不进入 Top 3

## 性价比评分模型

建议对通过硬筛选的候选方案进行归一化评分，分值越低越优。默认权重如下：

- `40%` 机票裸票价格
- `20%` 到 `深圳坪山站` 的补交通成本
- `25%` 全程总耗时
- `15%` 中转风险与折腾度

### 评分解释

- 价格仍然是第一权重
- 票面便宜但落地后补交通昂贵的方案，不应凭票面价格排到前面
- 总耗时对实际体验影响明显，应高于陆路补交通成本的权重
- 中转风险需要独立记分，防止高翻车风险方案挤进推荐结果

### 风险建议分级

- 低风险：
  - 直飞
  - 同机场保护中转
  - 中转时间相对充裕
- 中风险：
  - 同机场中转但时间较紧
  - 跨航站楼换乘
  - 到达后需要继续中长距离陆路接驳
- 高风险：
  - 自拼行程
  - 跨境后末班接驳不稳
  - 中转时间接近下限
  - 明显依赖多段衔接且容错低

### 统一比较口径

所有非深圳直达落地方案，必须补算到 `深圳坪山站` 的后续行程，包括：

- 陆路交通票价
- 换乘次数
- 额外等待时间
- 跨境通关或口岸风险
- 末班车风险

## 证据要求

执行者对每条候选航班至少要保留以下证据字段：

- 渠道名称
- 查询时间
- 航司与航班号
- 起飞时间与到达时间
- 是否中转
- 中转地与中转时长
- 票面价格
- 是否含税
- 是否裸票
- 是否可售
- 页面链接或可复核路径
- 抓取时间戳

如果同一航班在多个平台价格不一致，必须同时记录：

- 航司官方价格
- 主流 OTA 最低价格
- 价差
- 可能原因

可能原因包括但不限于：

- 平台补贴
- 新人价
- 会员价
- 券后价
- 余位紧张
- 附带隐性限制

## 历史趋势分析口径

后续执行者不得把无法验证的“完整历史票价曲线”写成事实。更稳妥的做法是把趋势分析拆成三层：

### 第一层：公开可见的趋势证据

- 平台价格日历
- 平台低价日历
- 价格提醒页面
- 近几日或近几周公开可见价格对比

### 第二层：邻近日期横向比较

比较 `2026-05-03` 到 `2026-05-08` 相邻日期同方向票价，判断 `2026-05-05` 是否明显偏高或偏低。

### 第三层：临近出发窗口规律

基于当前日期 `2026-04-07` 与出发日期 `2026-05-05` 之间的时间差，分析未来：

- `7 天`
- `14 天`
- `21 天`

内价格继续上涨、横盘或短暂回落的可能性。

### 替代指标

如果拿不到可靠长期历史数据，允许使用以下替代证据，但必须明确标注为推断依据：

- 同航线相邻日期价格带
- 同出发城市到不同落地城市的替代关系
- 节后尾段与工作日价格差
- 同平台低价区间

### 事实与推断分离

最终报告必须单独标明：

- 哪些结论来自已核实事实
- 哪些结论来自邻近日期比较或市场规律推断

## 异常处理规则

后续执行者必须显式处理以下异常：

### 查无满足条件航班

- 明确写出“无满足条件方案”
- 不得用隔夜到达或超长中转硬凑结果

### 跨境到达

- 到达 `香港 / 澳门` 时，必须单列：
  - 过关时间不确定性
  - 口岸或跨境交通风险
  - 到 `深圳坪山站` 的衔接复杂度

### 平台价格冲突

- 不直接选择最低价
- 需要说明最低价是否可复现、是否有附加条件

### 自拼行程

- 可以记录
- 但必须单独标注为 `高风险备选`
- 不与一体化联程混排

### 历史数据缺失

- 必须明确写出缺失项
- 必须说明改用了什么替代指标
- 不得臆造历史走势

## 最终输出格式

后续执行者最终必须输出以下结构：

### 1. 任务参数确认

复述全部搜索边界，确认执行没有跑偏。

### 2. 候选方案总表

建议包含以下列：

- 出发城市
- 到达城市
- 航司/航班号
- 起飞时间
- 到达时间
- 是否中转
- 中转地
- 中转时长
- 裸票价
- 补交通方式
- 补交通成本
- 到 `深圳坪山站` 总耗时
- 风险备注
- 报价渠道
- 抓取时间

### 3. Top 3 性价比方案

每个方案都必须回答：

- 为什么入选
- 适合什么人
- 主要风险
- 如果涨价多少就不值得买

### 4. 单独列出的特殊方案

- 票面最低价方案
- 总耗时最短方案
- 高风险但可能极便宜的备选方案

### 5. 购买时机判断

必须明确回答：

- 现在买还是继续等
- 如果等，最晚观察到哪一天
- 出现什么价格阈值应立即下单
- 哪些路线最值得继续盯

### 6. 简短结论摘要

结论区固定模板建议为：

- 综合最优：
- 最低价：
- 最省时间：
- 建议购买时间：
- 重点监控路线：
